## Acceptance Criteria

### Inngest Pipeline (7 stages — replaces the synchronous Phase 1 pipeline)
```
journey/ingest.requested
  └─ stage 1: validate_file      → file exists, mime type, size < 50MB
  └─ stage 2: parse_document     → PdfParserFactory (or PptxParser for .pptx)
  └─ stage 3: semantic_chunk     → 800 tokens, 100 overlap, table-safe
  └─ stage 4: classify_chunks    → Haiku classifier (4 types: core/contextual/procedural/reference)
  └─ stage 5: embed_chunks       → EmbedderService (both voyage + openai if configured)
  └─ stage 6: extract_concepts   → ConceptExtractorNode + ProficiencyVariable creation
  └─ stage 7: dual_write         → DualWriteService all chunks + concepts
journey/ingest.completed  (emitted on success)
journey/ingest.failed     (emitted on stage failure, retryable)
```

### Per-Stage Guarantees
- Each stage runs as `step.run(stageName, ...)` — individually retryable
- Idempotent: re-running a completed stage is safe (MERGE, not INSERT)
- Progress: each stage completion updates `ingestion_jobs.stage` and `progress_pct`
- Failure: if stage N fails after 3 retries, mark job `status: 'failed'`, emit `journey/ingest.failed`

### New Supabase table: `ingestion_jobs`
```sql
ingestion_jobs (
  id UUID PK, upload_id UUID FK, course_id UUID FK,
  status TEXT,  -- 'queued' | 'running' | 'completed' | 'failed'
  stage TEXT,   -- 'validate_file' | 'parse_document' | ... | 'dual_write'
  progress_pct INTEGER DEFAULT 0,
  total_chunks INTEGER, embedded_chunks INTEGER, extracted_concepts INTEGER,
  error_message TEXT, started_at TIMESTAMPTZ, completed_at TIMESTAMPTZ,
  created_at TIMESTAMPTZ DEFAULT now()
)
```

### API
- `POST /api/v1/uploads` → trigger file upload + fire `journey/ingest.requested`
- `GET /api/v1/ingestion-jobs/:id` → return job status + stage + progress
- `POST /api/v1/ingestion-jobs/:id/retry` → retry failed job from failed stage
