# P4-002: Rich Item Editor (Edit with Re-Validation)
**Epic:** 4.1 — Item Bank + Management
**Points:** 5 | **Depends:** P4-001 (item bank), P2-003 (30-rule validator), P2-004 (critic)
**Context packet:** docs/context-packets/CP-EPIC-4.1.md
**Specialist:** @frontend-specialist + @pipeline-specialist

**As a** faculty member
**I want** to directly edit any field of a question and have it automatically re-validated
**So that** I can make quick corrections without going through the full generation workbench

## Acceptance Criteria
- Route: `/items/:id/edit` (new screen — NOT in prototype)
- Form fields: vignette (textarea), stem (textarea), lead_in (text), each of 5 options (text + is_correct radio), explanation (textarea)
- Inline validation: on field blur, runs the 30 structural rules client-side (TypeScript validation shared from `packages/shared-types`)
- Save + Re-validate button → `PATCH /api/v1/items/:id` with full item body
- On save: backend runs:
  1. Full 30-rule validator
  2. Cover the Options (Sonnet)
  3. Critic Agent re-score (Opus) — only if validation passes
- Response includes new `validation_results`, `critic_composite_score`, `auto_route`
- Version saved to `assessment_item_versions` (immutable edit history from P2-007)
- "Revert to original" button — loads version from `assessment_item_versions` by index
- If only one option has `is_correct: true` — enforced by form (cannot save with 0 or 2+ correct)
- Correct answer change requires explicit confirmation modal ("Changing the correct answer will reset critic scores")
- God Component rule: editor splits into `VignetteEditor`, `StemEditor`, `OptionsEditor`, `ExplanationEditor`

## Smoke Test
```bash
# Edit a question's stem and save
curl -X PATCH "localhost:3001/api/v1/items/{itemId}" \
  -H "Authorization: Bearer $JWT" -H "Content-Type: application/json" \
  -d '{"stem":"A 52-year-old woman presents with chest pain...","vignette":"...updated..."}'
# Expected: { validation_passed: true, critic_composite_score: 4.1, auto_route: "auto_approve" }

# Version created
psql $SUPABASE_DB_URL -c "SELECT count(*) FROM assessment_item_versions WHERE item_id='{id}';"
# Expected: count > previous count (new version on every save)
```
