# P1-014: DualWriteService
**Epic:** 1.2 — Single Course Ingestion
**Points:** 3 | **Depends:** P1-004 (tables), P1-003 (DB clients)
**Context packet:** docs/context-packets/CP-EPIC-1.2.md

**As a** developer
**I want** a service that writes Supabase first then Neo4j with sync tracking
**So that** both databases stay consistent and failures are detectable

## Acceptance Criteria
- `DualWriteService` class at `backend/src/services/dual-write.service.ts`
- Generic: `dualWrite<T>(supabaseWrite, neo4jWrite): Promise<T>`
- Supabase fails → throw, do NOT write Neo4j
- Neo4j fails → `sync_status = 'failed'`, log, don't throw
- `reconcileFailures()` → retries all `sync_status = 'failed'` records
- Writes `neo4j_node_id` back to Supabase on Neo4j success
- `sync_status` values: `pending | synced | failed | orphaned`
- Reconcile endpoint: `POST /api/v1/admin/reconcile`

## Files to Create
- backend/src/services/dual-write.service.ts

## Smoke Test
```typescript
// Supabase write succeeds, Neo4j write fails → sync_status = 'failed'
// Run reconcile → sync_status → 'synced'
```
