# P2-019: KaizenML Data Linting Rules (5 Rules)
**Epic:** 2.4 — Data Quality + Faculty Trust
**Points:** 3 | **Depends:** P2-010 (Inngest installed), P1-023 (items exist)
**Context packet:** docs/context-packets/CP-EPIC-2.4.md
**Specialist:** @backend-specialist

**As a** system administrator
**I want** automated data quality checks running nightly
**So that** I'm alerted to Supabase/Neo4j drift and data integrity issues before they cause bugs

## Acceptance Criteria
- Inngest cron function: `backend/src/inngest/data-lint.function.ts`
- Schedule: nightly at 02:00 UTC (`cron: '0 2 * * *'`)
- 5 lint rules:
  1. **sync_status drift** — count `assessment_items` with `sync_status = 'failed'` → alert if > 5
  2. **orphan SubConcepts** — Neo4j SubConcepts with no `TEACHES` edges → alert if > 10% of total
  3. **null embeddings** — `content_chunk_embeddings` with both `voyage_embedding` AND `openai_embedding` NULL → alert if any
  4. **items without tags** — `assessment_items` with `bloom_level IS NULL` AND `created_at` > 24h ago → alert if > 0
  5. **generation_log orphans** — `generation_logs` with `status = 'running'` for > 2 hours → mark failed
- Supabase table: `kaizen_lint_runs (id, run_at, rule_id, result, count, threshold, passed, details)`
- Results endpoint: `GET /api/v1/admin/lint-results` (admin role only)
- Socket.io event `lint:alert` emitted to all admin users if any rule fails
