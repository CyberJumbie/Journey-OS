# P2-016: context_compiler ECD Sub-Steps
**Epic:** 2.3 — ECD + TaskShells
**Points:** 3 | **Depends:** P2-013 (TaskShells), P2-014 (ProficiencyVariables), P1-018 (context_compiler)
**Context packet:** docs/context-packets/CP-EPIC-2.3.md
**Specialist:** @pipeline-specialist

**As a** system
**I want** the context compiler to select the appropriate TaskShell and ProficiencyVariables for each generation
**So that** every question has ECD grounding from the start rather than it being retrofitted

## Acceptance Criteria
- `context_compiler` gains three new sub-steps (within the same node, executed sequentially):
  1. **Evidence Design sub-step** — identifies the evidentiary claim to be tested
  2. **Task Family selection** — queries Neo4j for matching TaskShells based on Bloom level and SubConcept
  3. **Instance Specification** — builds generation parameters (vignette length, option strategy, distractor type) from selected TaskShell properties
- Neo4j query in sub-step 2: `MATCH (pv:ProficiencyVariable)-[:MAPPED_TO]->(sc:SubConcept {name: $name}) MATCH (pv)-[:ASSESSED_BY]->(ts:TaskShell) RETURN ts ORDER BY ts.priority`
- Selected TaskShell injected into `WorkbenchState.taskShellId` and into all downstream prompts
- Prompt modification: `vignette-builder-system.txt` receives TaskShell parameters as structured context
- No new files — all changes inside `ContextCompilerNode.ts`

## Files to Modify
- `backend/src/pipeline/nodes/ContextCompilerNode.ts` — add 3 ECD sub-steps
- `backend/src/pipeline/prompts/vignette-builder-system.txt` — add TaskShell parameter section
- `packages/shared-types/src/index.ts` — add `taskShellId: string` to WorkbenchState
