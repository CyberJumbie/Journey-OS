## Acceptance Criteria

### UMLS API Integration
- UMLS REST API: `https://uts-ws.nlm.nih.gov/rest/` (free API key from NLM — `UMLS_API_KEY` env var)
- Auth: UMLS TGT (Ticket Granting Ticket) + service ticket pattern — implement `UmlsAuthService`
- Rate limit: 20 requests/second max — use Inngest step with `concurrency: { limit: 10 }`
- Search: `GET /search/current?string={subConceptName}&searchType=exact|approximate&returnIdType=concept`

### StandardTerm Node
```typescript
// Neo4j node type
interface StandardTerm {
  uuid: string;          // internal
  cui: string;           // UMLS CUI e.g. C0004096
  name: string;          // preferred name from UMLS
  snomedCtId?: string;   // SNOMED CT concept ID
  meshId?: string;       // MeSH descriptor ID
  icd10Code?: string;    // ICD-10 if applicable
  source: 'UMLS' | 'SNOMED' | 'MeSH';
  createdAt: string;
}

// Relationship
// SubConcept -[:GROUNDED_IN]-> StandardTerm
```

### Inngest Pipeline
- Function: `backend/src/inngest/umls-enrichment.function.ts`
- Trigger: `journey/umls.enrich.requested` (fired after P3-004 dedup completes)
- Per SubConcept:
  1. Search UMLS by name (exact match first, approximate if no exact)
  2. If match confidence ≥ 0.85: create `StandardTerm` node + `GROUNDED_IN` edge
  3. Fetch SNOMED CT ID via `GET /content/current/CUI/{cui}/atoms?sabs=SNOMEDCT_US`
  4. Fetch MeSH ID via `GET /content/current/CUI/{cui}/atoms?sabs=MSH`
  5. Store all identifiers on StandardTerm node

### Supabase Table
```sql
standard_terms (
  id UUID PK,
  sub_concept_id UUID,  -- conceptual reference (not strict FK)
  cui TEXT UNIQUE NOT NULL,
  name TEXT NOT NULL,
  snomed_ct_id TEXT,
  mesh_id TEXT,
  icd10_code TEXT,
  match_confidence FLOAT,
  source TEXT DEFAULT 'UMLS',
  neo4j_node_id TEXT,
  created_at TIMESTAMPTZ DEFAULT now()
)
```

### Admin UI
- Progress endpoint: `GET /api/v1/admin/umls-enrichment/status`
  - `{ total, enriched, failed, pending, lastRunAt }`
- Endpoint: `POST /api/v1/admin/umls-enrichment/run` — triggers Inngest job
- Admin dashboard: "UMLS Enrichment: 312/450 concepts grounded (69%)"

### How LCME Chain Benefits
After P3-018, the coverage chain query can use CUI-based matching:
```cypher
MATCH (lcme_el:LCME_Element)-[:MAPS_TO_TERM]->(st:StandardTerm)<-[:GROUNDED_IN]-(sc:SubConcept)
RETURN lcme_el.elementId, count(DISTINCT sc) AS grounded_concepts
```
This is more reliable than free-text name matching.
