# P4-004: Legacy Import Pipeline (Existing MSM Questions)
**Epic:** 4.1 — Item Bank + Management
**Points:** 5 | **Depends:** P1-012 (EmbedderService), P2-001 (tagger), P2-004 (critic)
**Context packet:** docs/context-packets/CP-EPIC-4.1.md
**Specialist:** @ingestion-specialist

**As a** faculty member
**I want** to import existing MSM exam questions into Journey OS
**So that** my pre-existing question library gets the same graph relationships, tags, and quality scores as AI-generated items

## Acceptance Criteria
- Import format: CSV with columns: `stem, vignette, option_a, option_b, option_c, option_d, option_e, correct_option, explanation, course_code, bloom_level, usmle_system`
- Endpoint: `POST /api/v1/imports` — multipart file upload (CSV only)
- Inngest function: `backend/src/inngest/legacy-import.function.ts`
- Per-row pipeline:
  1. Parse + validate CSV row (required fields check)
  2. Create `AssessmentItem` in Supabase (`source: 'legacy_import'`, `status: 'draft'`)
  3. Embed stem via EmbedderService → `assessment_item_embeddings`
  4. Run tagger (Haiku) — fill missing tags from CSV if partial
  5. Run validator (30 rules — do NOT auto-reject legacy items on fail, just flag)
  6. Run critic (Opus) — score each legacy item
  7. DualWriteService → Neo4j `AssessmentItem` node + `TARGETS` relationships
- New Supabase column: `assessment_items.source TEXT DEFAULT 'ai_generated'` — legacy items = `'legacy_import'`
- Import job tracking: `import_jobs (id, filename, total_rows, processed_rows, failed_rows, status, created_at)`
- Failure handling: row-level failure logged, never aborts whole batch
- Result endpoint: `GET /api/v1/imports/:id` — progress + per-row errors
- Admin UI: `POST /api/v1/imports` accessible from admin panel, not faculty UI
