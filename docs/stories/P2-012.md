# P2-012: Socket.io Notifications
**Epic:** 2.2 — Review Mode + Bulk Generation
**Points:** 3 | **Depends:** P2-010 (Inngest fires events)
**Context packet:** docs/context-packets/CP-EPIC-2.2.md
**Specialist:** @backend-specialist

**As a** faculty member
**I want** to receive real-time notifications when my batch completes or when a question needs review
**So that** I don't have to keep refreshing the page

## Acceptance Criteria
- Socket.io installed on backend: `npm install socket.io` — singleton at `backend/src/lib/SocketServer.ts`
- Socket.io client on frontend: `npm install socket.io-client` — `frontend/src/lib/socket.ts`
- Auth: socket connection sends JWT in handshake `auth.token` — server validates before allowing connection
- Events emitted by backend to room `user:{userId}`:
  - `batch:completed` → `{ batchId, completedCount, failedCount }`
  - `batch:item:completed` → `{ batchId, itemId, status }`
  - `review:needed` → `{ itemId, reason }` (when review_router routes to faculty_review)
  - `sync:failed` → `{ entityId, entityType }` (DualWrite Neo4j failure)
- Frontend: `useNotifications()` hook — connects socket, accumulates events in state
- NotificationBell atom in header — red dot badge on unread count
- NotificationDropdown molecule — lists last 10 notifications, click navigates to relevant screen
- Graceful degradation: if Socket.io unavailable, UI still works — polling fallback for batch status
