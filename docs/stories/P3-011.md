# P3-011: Faculty Dashboard (/dashboard)
**Epic:** 3.3 — Faculty Dashboard + Coverage Visualization
**Points:** 5 | **Depends:** P3-007 (heatmap data), P2-021 (generation history), P3-008 (gap priorities)
**Context packet:** docs/context-packets/CP-EPIC-3.3.md
**Specialist:** @frontend-specialist

**As a** faculty member
**I want** a real-time dashboard showing my question bank health, coverage gaps, and recent activity
**So that** I can see the impact of my work without manually querying the database

## Acceptance Criteria
- Route: `/dashboard` (wires existing `FacultyDashboard` prototype screen)
- Endpoint: `GET /api/v1/dashboard` — aggregates all dashboard data in one call (< 500ms)
- Response matches prototype shape exactly (see 06_SCREEN_BACKEND_MAP.md):
  ```typescript
  interface FacultyDashboardData {
    stats: {
      total_items: number;
      approved_items: number;
      approval_rate: number;
      coverage_score: number;       // avg coverage across user's courses
      active_students: number;      // Phase 5 — hardcode 0 for now
      sparklines: number[][];
      changes: string[];            // e.g. ["+12 this week"]
    };
    courses: Course[];              // user's courses with coverage %
    recent_activity: ActivityItem[];  // last 10 generation events
    top_gaps: GapCell[];            // top 5 from P3-008
  }
  ```
- `useDashboard()` hook with 60-second polling interval (not real-time — no socket needed)
- KPI cards: Total Items, Approval Rate, Coverage Score, Active Courses
- Sparklines: Recharts `<Sparkline>` — 7-day trend for each KPI
- Gap callout: "⚠ 3 high-priority gaps — [Fill now →]" links to `/analytics/gaps`
- Courses list: sorted by coverage (lowest first) to surface at-risk courses
