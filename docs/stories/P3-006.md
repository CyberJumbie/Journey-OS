# P3-006: SLO → ILO FULFILLS Linking (Faculty Review)
**Epic:** 3.1 — Multi-Course Ingestion
**Points:** 3 | **Depends:** P3-005 (SLOs extracted), P1-005 (ILOs seeded in Layer 1)
**Context packet:** docs/context-packets/CP-EPIC-3.1.md
**Specialist:** @frontend-specialist + @backend-specialist

**As a** course director
**I want** to confirm which Institutional Learning Outcomes each course SLO fulfills
**So that** the LCME compliance chain (ILO ← SLO ← AssessmentItem) is built on verified data

## Acceptance Criteria
### AI-Suggested Linking
- After SLO extraction: Haiku auto-suggests ILO matches for each SLO
- Prompt: embed SLO text → nearest ILO by cosine similarity (top 3 candidates)
- Store suggestions in `slo_ilo_suggestions (slo_id, ilo_id, similarity, accepted BOOLEAN)`

### Faculty Review UI
- Route: `/admin/ilo-management` (wires existing `ILOManagement` prototype screen)
- `GET /api/v1/slos?courseId=X&status=pending` — SLOs awaiting ILO link confirmation
- Each SLO shown with top 3 suggested ILOs + similarity scores
- Faculty selects one (or "None — create new ILO") and clicks Accept
- `PATCH /api/v1/slos/:id/fulfills` → body `{ iloId: string }`

### Neo4j
```cypher
MATCH (slo:SLO {uuid: $sloUuid})
MATCH (ilo:ILO {uuid: $iloUuid})
MERGE (slo)-[:FULFILLS]->(ilo)
```

### Supabase
- `slos.ilo_id UUID` — FK to ILOs table (ILOs are also in Supabase as reference data)
- `slos.fulfills_status TEXT` — 'pending' | 'linked' | 'skipped'
