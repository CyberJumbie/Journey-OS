# P2-017: ProficiencyVariable ASSESSED_BY TaskShell Relationships
**Epic:** 2.3 — ECD + TaskShells
**Points:** 2 | **Depends:** P2-013 (TaskShells), P2-014 (ProficiencyVariables)
**Context packet:** docs/context-packets/CP-EPIC-2.3.md
**Specialist:** @backend-specialist

**As a** system
**I want** all existing ProficiencyVariables linked to the appropriate TaskShells
**So that** the ECD relationship graph is complete for all concepts extracted in Phase 1

## Acceptance Criteria
- One-time migration script: `seeder/src/seed-pv-taskshell-links.ts`
- Algorithm: for each ProficiencyVariable, find TaskShells where `ts.bloomMin <= pv.bloomLevelGuess <= ts.bloomMax`
- Primary link (priority 1): TaskShell with narrowest matching Bloom range
- Secondary links (priority 2–3): next 1–2 matching TaskShells
- Cypher: `MERGE (pv)-[ab:ASSESSED_BY {priority: $priority}]->(ts)`
- Script run once on existing graph: `pnpm seed:pv-links`
- Also called automatically in P2-014 `ConceptExtractorNode` for new SubConcepts going forward
- `scripts/validate-graph.ts`: ASSESSED_BY count ≥ SubConcept count (every PV has at least 1 link)

## Files to Create
- `seeder/src/seed-pv-taskshell-links.ts`

## Files to Modify
- `seeder/package.json` — add `seed:pv-links`
- `scripts/validate-graph.ts` — add ASSESSED_BY relationship count check

## Smoke Test
```cypher
MATCH (pv:ProficiencyVariable)-[ab:ASSESSED_BY]->(ts:TaskShell)
RETURN count(ab) AS link_count, count(DISTINCT pv) AS pv_with_links
```
