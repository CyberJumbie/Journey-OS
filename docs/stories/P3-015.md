## Acceptance Criteria
- Route: `/admin/lcme-compliance-heatmap` (wires existing `LCMEComplianceHeatmap` prototype screen)
- 12 LCME Standards (seeded in Phase 1 as LCME_Standard nodes) × N Elements per standard
- Coverage color coding:
  - Gray: 0% (no evidence)
  - Red `#d32f2f`: < 50%
  - Amber `#f59e0b`: 50–79%
  - Green `#69a338`: ≥ 80%

### Coverage Chain Query
```cypher
// P3-016 builds this — P3-015 uses the result
MATCH (lcme_el:LCME_Element)-[:BELONGS_TO]->(std:LCME_Standard)
OPTIONAL MATCH (lcme_el)<-[:ALIGNS_TO]-(ilo:ILO)<-[:FULFILLS]-(slo:SLO)<-[:HAS_SLO]-(c:Course)
OPTIONAL MATCH (slo)<-[:MAPS_TO]-(sc:SubConcept)<-[:TARGETS]-(ai:AssessmentItem {status: 'approved'})
RETURN std.name, lcme_el.elementId, lcme_el.name,
       count(DISTINCT ai) AS evidence_count,
       CASE WHEN count(DISTINCT ai) = 0 THEN 0
            WHEN count(DISTINCT ai) < 3 THEN 50
            ELSE 100 END AS coverage_pct
ORDER BY std.name, lcme_el.elementId
```

### API
- Endpoint: `GET /api/v1/admin/lcme/coverage` (matches screen_backend_map contract)
- Response: `{ standards: string[], elements: string[], coverage: Record<elementId, pct> }`
- Cached: Redis cache 10-minute TTL (heavy Cypher query — don't run on every page load)
- If Redis unavailable: run query directly (graceful degradation)

### Frontend
- `useLcmeCoverage()` hook
- Click element cell → navigate to `/admin/lcme-element-drill-down?elementId=X`
