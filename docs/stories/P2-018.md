# P2-018: TEACHES_VERIFIED Workflow
**Epic:** 2.4 — Data Quality + Faculty Trust
**Points:** 5 | **Depends:** P1-013 (TEACHES edges exist), P1-024 (auth works)
**Context packet:** docs/context-packets/CP-EPIC-2.4.md
**Specialist:** @frontend-specialist + @backend-specialist

**As a** faculty member
**I want** to confirm or reject the AI-extracted content-concept mappings for my course
**So that** only verified relationships participate in coverage reporting and LCME compliance chains

## Acceptance Criteria

### Backend
- New endpoint: `GET /api/v1/courses/:id/concept-mappings` — returns all `TEACHES` edges for a course with chunk excerpt, concept name, confidence score
- New endpoint: `PATCH /api/v1/concept-mappings/:id/verify` — body `{ action: 'verify' | 'reject' }`
- On `verify`: `MERGE (cc)-[:TEACHES_VERIFIED]->(sc)` in Neo4j, update `teaches_verifications` Supabase table
- On `reject`: delete `TEACHES` relationship (keeps `TEACHES_VERIFIED` untouched if it existed)
- Supabase table: `teaches_verifications (id, chunk_id, sub_concept_id, verified_by, action, created_at)`

### Frontend
- Route: `/courses/:id/concept-review` — SubConcept Review Queue
- `useConceptMappings(courseId)` hook — fetches pending TEACHES edges
- ConceptMappingCard organism: shows chunk excerpt (200 chars), concept name, confidence badge, Verify/Reject buttons
- Bulk actions: "Verify All High Confidence (>0.85)" button
- Progress indicator: "12 of 47 mappings reviewed"
- After review complete: redirect to `/courses/:id` with success toast
- Atoms needed: `ConfidenceBadge` (green/amber/red by threshold), `ChunkExcerpt`
