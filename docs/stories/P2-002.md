**As a** faculty member
**I want** the system to detect near-duplicate questions before saving them
**So that** my question bank doesn't accumulate redundant items that would make exams repetitive

## Acceptance Criteria
- Node: `backend/src/pipeline/nodes/DedupDetectorNode.ts` — runs after `distractor_generator`, before `validator`
- Embeds the new question stem using active `EMBEDDING_SEARCH_PROVIDER`
- Queries pgvector: cosine similarity against all existing `approved` + `draft` items for same `course_id`
- Thresholds: similarity ≥ 0.95 → `auto_reject` (too similar); 0.85–0.95 → `flag_for_review`; < 0.85 → `pass`
- STATE updates: `isDuplicate: boolean`, `dupSimilarity: number`, `dupItemId: string | null`
- If `auto_reject`: set `pipelineStatus: 'failed'`, emit TEXT_MESSAGE explaining which item it's a dup of
- If `flag_for_review`: continue pipeline, emit TEXT_MESSAGE warning, set `autoRoute: 'faculty_review'`
- Supabase: write `dedup_similarity`, `dedup_status`, `dedup_item_id` to `assessment_items` row
- New RPC function: `search_items_by_stem_voyage(vector(1024), course_id, threshold, limit)` and `search_items_by_stem_openai(vector(1536), ...)`
- Item stem embeddings stored in new table `assessment_item_embeddings` (same dual-column pattern as chunk embeddings)

## Failure Modes
1. `assessment_item_embeddings` empty on first run → no dups detected (correct behavior — skip dedup, continue)
2. Embedding call fails → log error, set `dedup_status: 'skipped'`, continue pipeline (never block generation)
3. Same stem asked in review mode → dedup should exclude the item being reviewed from similarity search
