# P2-006: Self-Correction Loops
**Epic:** 2.1 — Pipeline Completion
**Points:** 3 | **Depends:** P2-003 (validator), P2-005 (review_router knows route)
**Context packet:** docs/context-packets/CP-EPIC-2.1.md
**Specialist:** @pipeline-specialist

**As a** faculty member
**I want** the pipeline to automatically retry generation when validation fails
**So that** I get a usable question instead of a failure message for fixable problems

## Acceptance Criteria
- Retry logic in `ReviewRouterNode` or as a separate orchestration wrapper in `graph.ts`
- Max retries: **2** (never more — Opus cost, latency)
- Retry conditions: validation failed (not BLOCKING), critic composite < 3.0
- On retry: rebuild context with modified prompt (`retry_count` injected into prompt template)
  - Retry 1 prompt suffix: "Previous attempt failed rule {failedRule}. Fix: {ruleDescription}."
  - Retry 2 prompt suffix: "Two prior attempts failed. Prioritize NBME compliance over vignette length."
- `retry_count` stored in `WorkbenchState` and in `generation_logs`
- If all 3 attempts fail → `auto_route: 'faculty_review'`, `rejection_reason: 'max_retries_exceeded'`
- TEXT_MESSAGE emitted on each retry: "Retrying (attempt {n}/3)..."
- No infinite loops — `retry_count` checked at graph entry, not after each node

## Files to Modify
- `backend/src/pipeline/graph.ts` — add retry edge from review_router back to vignette_builder
- `backend/src/pipeline/nodes/ReviewRouterNode.ts` — emit retry signal
- `packages/shared-types/src/index.ts` — add `retryCount: number` to WorkbenchState
