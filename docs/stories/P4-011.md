# P4-011: SuperAdmin + Institutional Admin Screens
**Epic:** 4.3 — LOD Enrichment + Admin
**Points:** 5 | **Depends:** P1-024 (auth + roles), P3-007 (analytics data)
**Context packet:** docs/context-packets/CP-EPIC-4.3.md
**Specialist:** @frontend-specialist + @backend-specialist

**As a** superadmin / institutional admin
**I want** dedicated admin dashboards for managing users, institutions, and system health
**So that** I can provision new faculty, manage course assignments, and monitor system-wide health

## Acceptance Criteria

### Admin Dashboard
- Route: `/admin` (wires `AdminDashboard` prototype screen)
- Endpoint: `GET /api/v1/admin/dashboard` — system-wide stats
- Stats: total institutions, total faculty, total courses, total approved items, total exams, storage used, socket connections
- Quick actions: "Invite Faculty", "Create Course", "Run Lint", "Trigger UMLS Backfill"

### User Management
- Route: `/admin/users` (wires `UserManagement` prototype)
- Endpoint: `GET /api/v1/admin/users?role=X&institutionId=Y&search=Z&page=N`
- Actions: invite user (`POST /api/v1/admin/users/invite`), deactivate, change role
- Invite sends Supabase magic link email with pre-set role in JWT claims

### Institutional Admin
- Route: `/institution` (wires `InstitutionalAdminDashboard` prototype)
- Endpoint: `GET /api/v1/institution/dashboard` — institution-scoped version of admin dashboard
- Course management: list all courses, assign faculty to course, view course health
- Framework configuration: `GET/PATCH /api/v1/institution/frameworks` — enable/disable framework families per institution

### Role hierarchy
```
superadmin      → all institutions, all data
institution_admin → own institution only
course_director → own courses only (existing)
faculty         → own generated items only (existing)
student         → own sessions only (Phase 5)
```

- Middleware: `requireRole('admin' | 'institution_admin')` on all admin routes
- RLS: Supabase policies already restrict by `institution_id` from JWT claim
