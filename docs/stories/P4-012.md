# P4-012: Notification System (Supabase Realtime + Socket.io)
**Epic:** 4.3 — LOD Enrichment + Admin
**Points:** 3 | **Depends:** P2-012 (Socket.io base), P4-008 (exam sessions)
**Context packet:** docs/context-packets/CP-EPIC-4.3.md
**Specialist:** @backend-specialist

**As a** faculty member or student
**I want** to receive notifications for important events without refreshing
**So that** I stay informed about exam assignments, batch completions, and review requests

## Acceptance Criteria

### Notification Types (extends P2-012)
Phase 2 added: `batch:completed`, `batch:item:completed`, `review:needed`, `sync:failed`
Phase 4 adds:
- `exam:assigned` → student receives when faculty assigns an exam
- `exam:submitted` → faculty receives when a student submits
- `exam:results_ready` → student receives when scoring completes
- `import:completed` → admin receives when legacy import finishes
- `umls:enrichment_complete` → admin receives when UMLS backfill run finishes

### Supabase Realtime (new in Phase 4)
- `notifications` Supabase table with Realtime enabled
- Backend writes notification rows; Supabase broadcasts to subscribed clients
- Frontend: `useRealtimeNotifications()` hook using `supabase.channel('notifications').on('postgres_changes', ...)`
- This supplements Socket.io (which handles server-push); Supabase Realtime handles DB-change-push
- Notifications table: `{ id, user_id, type, title, body, data JSONB, read BOOLEAN, created_at }`

### NotificationCenter (full page)
- Route: `/notifications` — full notification history
- `useNotifications(userId)` hook — queries `GET /api/v1/notifications?limit=50&read=false`
- Mark all read: `PATCH /api/v1/notifications/read-all`
- NotificationBell badge count driven by unread count from Supabase Realtime subscription
