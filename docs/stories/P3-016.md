# P3-016: LCME Coverage Chain Query (Full Evidence Trail)
**Epic:** 3.4 — LCME Compliance MVP
**Points:** 3 | **Depends:** P3-015 (LCME dashboard), P3-006 (FULFILLS edges)
**Context packet:** docs/context-packets/CP-EPIC-3.4.md
**Specialist:** @backend-specialist

**As an** Associate Dean
**I want** to drill into any LCME element and see the full evidence chain from element to assessment item
**So that** accreditors can trace exactly how we demonstrate compliance for each element

## Acceptance Criteria
- Route: `/admin/lcme-element-drill-down?elementId=X` (wires existing `LCMEElementDrillDown` prototype)
- Endpoint: `GET /api/v1/admin/lcme/elements/:elementId/evidence`
- Full chain query — every hop traced:
  ```
  LCME_Element → ILO → SLO → SubConcept → AssessmentItem
  ```
- Response:
  ```typescript
  interface LcmeEvidenceChain {
    element: { id: string; name: string; standard: string; description: string };
    ilos: {
      name: string;
      slos: {
        text: string; courseCode: string;
        subconcepts: {
          name: string;
          items: { id: string; stem: string; status: string; criticScore: number }[];
        }[];
      }[];
    }[];
    totalItems: number;
    coveragePct: number;
  }
  ```
- "Missing links" section: identifies any broken chain steps (e.g., ILO with no SLO, SLO with no SubConcept)
- All evidence counted only when `AssessmentItem.status = 'approved'` — draft items don't count
- Response time < 2 seconds per element (optimize Cypher with node indexes)

## Files to Modify
- `backend/src/repositories/lcme.repository.ts` — add `getElementEvidence(elementId)`
- `backend/src/controllers/lcme.controller.ts` — add element evidence endpoint
