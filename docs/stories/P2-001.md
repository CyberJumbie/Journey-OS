# P2-001: tagger Node
**Epic:** 2.1 — Pipeline Completion
**Points:** 3 | **Depends:** P1-023 (graph_writer exists, 7-node pipeline complete)
**Context packet:** docs/context-packets/CP-EPIC-2.1.md
**Specialist:** @pipeline-specialist

**As a** faculty member
**I want** every generated question automatically tagged with Bloom level, USMLE system/discipline, difficulty estimate, ACGME domain, and EPA
**So that** I can filter and report on question coverage without manually classifying each item

## Acceptance Criteria
- Node: `backend/src/pipeline/nodes/TaggerNode.ts` — runs after `graph_writer`
- Model: Claude Haiku (`claude-haiku-4-5`) — cheap, structured output
- Tags extracted: `bloom_level` (1–6), `usmle_system`, `usmle_discipline`, `difficulty` (1–5), `acgme_domain`, `epa_number`
- Prompt in: `backend/src/pipeline/prompts/tagger-system.txt`
- Output: strict JSON `{ bloom_level, usmle_system, usmle_discipline, difficulty, acgme_domain, epa_number }`
- Writes tags to `assessment_items` columns (each tag is a separate column — no JSONB)
- DualWriteService: update Neo4j `AssessmentItem` node with `bloomLevel`, `difficulty` properties
- STATE_DELTA emitted: `{ tags: { bloom_level, usmle_system, ... } }` — visible in right panel
- TEXT_MESSAGE: "Tagging: Bloom {level}, USMLE {system}..."
- If Haiku returns malformed JSON: log warning, write `null` to tag columns, do not throw

## Failure Modes
1. Haiku returns prose instead of JSON → wrap in try/catch, write nulls, emit warning TEXT_MESSAGE
2. USMLE system name doesn't match NODE_REGISTRY → use fuzzy match against seeded USMLE_System node names
3. Pipeline order: tagger MUST run after graph_writer (needs `itemId` in state)
